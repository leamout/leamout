# Recording storage — BYOS only

Leamout Cloud requires customer-owned S3-compatible storage for permanent recordings. Leamout retains the recording metadata, local temporary staging, upload worker, and control-plane API. No platform bucket, MinIO service, or fallback destination is provided.

An organization configures an S3-compatible storage integration through `/v1/storage-integrations/`. Each integration records endpoint, region, bucket, access-key ID, encrypted secret, and addressing mode. Public HTTPS and SSRF network checks are enforced. The test endpoint verifies write, read and delete permissions.

When an upload begins, the worker selects the organization's active integration, creates a tenant-prefixed object key, and persists `storage_integration_id`, key, provider, and bucket before writing bytes. Retries reuse the pinned integration, including after it is disabled. Playback and deletion always use the historical integration ID. No active integration means the upload fails closed and follows bounded retry/failure handling; normal calls can run without recording storage.

The object key is generated by Leamout: `organizations/{organization_id}/recordings/{yyyy}/{mm}/{dd}/{recording_id}.{ext}`. The database composite foreign key and runtime tenant-scoping prevent cross-organization integration ownership.

## Temporary staging and failure handling

FreeSWITCH initially writes audio to a shared local staging volume used by the ingestion worker. Successful ingestion deletes the staged file. Failed uploads follow ten configured attempts with exponential backoff and are never redirected into a Leamout bucket. Operators must provide a staged-file cleanup and capacity policy.

## Migration warning

Previous managed recordings have `storage_integration_id IS NULL` with a persisted storage key. They are **not** automatically reassigned. Before removing an existing MinIO volume:

1. Inventory and back up the existing recording objects and database rows.
2. Create and verify each customer's S3-compatible integration.
3. Copy objects, validate their integrity, and transactionally reassign each legacy recording to its owning organization's integration and bucket.
4. Verify playback and deletion before removing the old object store.

This refactor does not implement or run data migration. Any unconverted legacy recording deliberately fails closed instead of reading an unrelated customer bucket.
